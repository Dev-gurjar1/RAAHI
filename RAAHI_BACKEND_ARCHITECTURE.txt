                    RAAHI - BACKEND ARCHITECTURE & SPECIFICATION
================================================================================

1. CURRENT BACKEND STATUS
--------------------------------------------------------------------------------
Is a real backend currently present in this project?
-> NO. Currently, RAAHI runs on a high-performance Client-Side State Store 
   (located at `src/services/store.ts` and `src/services/seedData.ts`).
   It uses reactive event listeners and localStorage to simulate backend operations
   like posting guide requests, placing bids, processing payments, and identity checks.

To scale RAAHI into a production web application, you should attach a dedicated
REST / GraphQL / WebSocket backend API as specified below.

2. RECOMMENDED BACKEND TECH STACKS
================================================================================

OPTION A: Node.js + Express / NestJS + PostgreSQL (RECOMMENDED)
--------------------------------------------------------------------------------
- Language: TypeScript
- Framework: Node.js with Express.js or NestJS
- Database: PostgreSQL (with Prisma ORM or Drizzle ORM)
- Real-Time: Socket.io (for live guide bid notifications)
- Auth: JWT (JSON Web Tokens) + Firebase Auth / Clerk / Supabase Auth
- Payments: Razorpay / Stripe API (Escrow workflow)
- Hosting: Vercel, AWS ECS, Railway, Render

OPTION B: Python FastAPI + PostgreSQL / Supabase
--------------------------------------------------------------------------------
- Language: Python 3.11+
- Framework: FastAPI (Async, high speed)
- Database: PostgreSQL (SQLAlchemy / SQLModel)
- AI Integration: LangChain / Google Gemini API SDK / OpenAI SDK
- Ideal if: You plan to add deep AI travel recommendation features.

OPTION C: Supabase (Serverless BaaS - FASTEST TO DEPLOY)
--------------------------------------------------------------------------------
- Postgres Database built-in
- Realtime WebSockets for guide bids built-in
- Built-in Authentication (Phone OTP, Google OAuth)
- Storage for Guide ID Document Verification uploads

3. DATABASE SCHEMA & ENTITY DESIGN (PostgreSQL SQL / Prisma)
================================================================================

A. USERS TABLE (`users`)
   - id: UUID (Primary Key)
   - email: VARCHAR (Unique)
   - phone: VARCHAR (Unique)
   - password_hash: VARCHAR
   - role: ENUM ('TOURIST', 'GUIDE', 'ADMIN')
   - full_name: VARCHAR
   - avatar_url: TEXT
   - city: VARCHAR
   - created_at: TIMESTAMP

B. GUIDE PROFILES TABLE (`guide_profiles`)
   - id: UUID (Primary Key)
   - user_id: UUID (Foreign Key -> users.id)
   - rating: DECIMAL(3,2) (Default 5.00)
   - review_count: INT
   - experience_years: INT
   - languages: TEXT[] (Array of languages)
   - service_areas: TEXT[]
   - starting_price: DECIMAL(10,2)
   - completed_tours: INT
   - verification_status: ENUM ('PENDING', 'UNDER_REVIEW', 'VERIFIED', 'REJECTED')
   - verification_badges: TEXT[]
   - bio: TEXT
   - id_document_url: TEXT

C. GUIDE REQUESTS TABLE (`guide_requests`) - Tourist Bidding Request
   - id: UUID (Primary Key)
   - tourist_id: UUID (Foreign Key -> users.id)
   - destination: VARCHAR
   - date: DATE
   - travelers_count: INT
   - duration_hours: INT
   - interests: TEXT[]
   - budget: DECIMAL(10,2)
   - special_requirements: TEXT
   - status: ENUM ('OPEN', 'BIDDED', 'ACCEPTED', 'CLOSED')
   - created_at: TIMESTAMP

D. TOUR OFFERS TABLE (`tour_offers`) - Guide Bids
   - id: UUID (Primary Key)
   - request_id: UUID (Foreign Key -> guide_requests.id)
   - guide_id: UUID (Foreign Key -> guide_profiles.id)
   - price: DECIMAL(10,2)
   - pitch: TEXT
   - included_services: TEXT[]
   - badge_label: ENUM ('Best Match', 'Best Value', 'Most Experienced')
   - status: ENUM ('PENDING', 'ACCEPTED', 'REJECTED')
   - created_at: TIMESTAMP

E. FAIR PRICE RULES TABLE (`fair_price_rules`) - Price Checker Engine
   - id: UUID (Primary Key)
   - destination: VARCHAR
   - category: ENUM ('AUTO_TAXI', 'GUIDE_HERITAGE', 'STREET_FOOD', 'CAB')
   - route_or_item: VARCHAR
   - price_range_min: DECIMAL(10,2)
   - price_range_max: DECIMAL(10,2)
   - unit: VARCHAR
   - trusted_source: VARCHAR
   - last_updated: DATE

F. BOOKINGS & ESCROW TABLE (`bookings`)
   - id: UUID (Primary Key)
   - tourist_id: UUID (Foreign Key -> users.id)
   - guide_id: UUID (Foreign Key -> guide_profiles.id)
   - offer_id: UUID (Foreign Key -> tour_offers.id)
   - total_price: DECIMAL(10,2)
   - platform_fee: DECIMAL(10,2) (e.g. 10%)
   - guide_earnings: DECIMAL(10,2)
   - payment_status: ENUM ('PENDING', 'PAID_ESCROW', 'RELEASED', 'REFUNDED')
   - razorpay_payment_id: VARCHAR
   - booking_status: ENUM ('UPCOMING', 'ACTIVE', 'COMPLETED', 'CANCELLED')

4. KEY REST API ENDPOINTS SPECIFICATION
================================================================================

AUTH ENDPOINTS:
- POST /api/v1/auth/signup          (Register Tourist or Guide)
- POST /api/v1/auth/login           (Login & receive JWT Token)
- GET  /api/v1/auth/me              (Fetch current profile context)

FAIR PRICE ENGINE ENDPOINTS:
- GET  /api/v1/fair-prices/check    (Params: service, from, to, quotedPrice)
  -> Returns estimated range, overcharge warning, data source, confidence score.
- GET  /api/v1/fair-prices/rules    (Fetch union & benchmark tariffs by city)

BIDDING & GUIDE MARKETPLACE ENDPOINTS:
- POST /api/v1/requests             (Tourist posts custom trip request)
- GET  /api/v1/requests/:id         (Fetch request details)
- GET  /api/v1/requests/:id/offers  (Fetch guide bids - Rahul, Amit, Mohit)
- POST /api/v1/requests/:id/offers  (Guide submits a bid offer)
- POST /api/v1/offers/:id/accept    (Tourist accepts offer -> creates booking)

PAYMENT & ESCROW ENDPOINTS:
- POST /api/v1/payments/create-order(Initiate Razorpay/Stripe checkout)
- POST /api/v1/payments/webhook     (Verify payment signature & hold escrow)
- POST /api/v1/payments/release     (Release funds to guide after tour completion)

AI PLANNER ENDPOINT:
- POST /api/v1/ai/generate-itinerary(Calls Gemini AI model with real RAAHI DB places)

5. HOW TO INTEGRATE THE BACKEND WITH FRONTEND (`src/services/store.ts`)
================================================================================

1. Install Axios or use native `fetch`:
   `npm install axios`

2. Create an API client service file `src/services/api.ts`:
   ```typescript
   import axios from 'axios';

   const api = axios.create({
     baseURL: import.meta.env.VITE_API_URL || 'http://localhost:5000/api/v1',
   });

   export default api;
   ```

3. Replace local arrays in `store.ts` with API calls:
   ```typescript
   export const fetchGuideOffers = async (requestId: string) => {
     const response = await api.get(`/requests/${requestId}/offers`);
     return response.data;
   };
   ```
